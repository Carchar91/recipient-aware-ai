# Known limitations

1. **No independent efficacy evidence.** The preserved synthetic Codex records include the earlier 20-run pilot and eight later rc.2 sessions, not observed human outcomes or independent human grading. The pilot comparison was partially contaminated. No new model calls were made for this public release. Engineering PASS covers software and fixtures, not practical effectiveness. See [the evidence history](EVALUATION.md).
2. **Not every semantic error is machine-detectable.** Valid JSON can contain falsehood, manipulation, poor advice or unreasonable hypotheses. An exact evidence quote is not proof that the evidence is true or that the conclusion follows.
3. **No reading of minds.** Motives, reactions and status concerns remain interpretations. Reverse is not a substitute for asking a real recipient.
4. **Prompt injection remains a risk.** Input separation and explicit instructions help define intended behavior but are not a security boundary. The runner provides no external tools; a host with tools needs independent permission controls.
5. **Not professional advice.** The package must not invent or certify bank, legal, regulatory, medical or employment rules. Human review and appropriate primary evidence are needed.
6. **No outcome guarantee.** Agreement is not the sole success criterion. The approach has not been shown to outperform ordinary prompting on a representative independent test set.
7. **Multilingual uncertainty.** Russian and Thai synthetic inputs exercise input handling and specify human review criteria. They do not establish validated translation quality or cultural expertise.
8. **Host behavior differs.** SKILL.md packaging and invocation metadata were structurally checked. Installation and live invocation were not verified across all hosts. No marketplace listing exists as a result of this package.
9. **Reproducible specification, not deterministic generation.** Instructions, inputs and hashes can be reproduced. Model snapshots and provider behavior may differ, and repeated model answers may vary.
10. **Development fixtures are not a blind benchmark.** The reference answers and expected decisions are public to the maintainer. They may bias testing. Use separately authored, consent-cleared held-out tasks for stronger evidence.
11. **Network and storage.** An explicit live call sends text to OpenAI. store=false is not a blanket data-retention guarantee. Run artifacts can contain the submitted text and must be protected.
12. **Experimental release and licence scope.** The owner approved Apache-2.0 for his own materials; third-party terms remain separate. The legacy transfer tool only supports initial private drafts, not this public-release procedure. Earlier pending-licence/private-status reports are unchanged historical snapshots. Public availability requires unauthenticated GitHub readback, not an authorised session alone.
13. **Package form.** Ordinary use selects one standalone skill; the Python harness uses a source checkout. A standalone wheel with bundled protocol assets is not tested or published. The pinned dependencies were installed successfully in a clean Python 3.14.4 environment; this does not establish compatibility across every supported Python version or operating system. The new Rail file-delivery rule has not had a new model trial; native Excel/LibreOffice and ChatGPT plugin integration remain untested.
