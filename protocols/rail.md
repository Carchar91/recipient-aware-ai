# Rail

Prepare the usable execution kit, rather than a description of work the recipient still has to organize.

## Use and inputs
Use when a task hides file selection, calculations, contact lookup, message drafting or handoff design. Use supplied specifications, contacts, files, roles and permissions. Reduce unnecessary organizational effort, not the person's judgment. Do not invent missing details or build a new system when one message and one small table suffice.

## Procedure
1. Establish the concrete result and completion criterion. Select the correct supplied version and identify the authorized human actor, decision owner and result recipient.
2. Do available preparation now: choose relevant material, calculate supported quantities, draft the exact request, and prepare the smallest useful table or other artifact. When the task needs working documents and file writing is available and authorized, create the necessary files: editable XLSX with formulas for linked calculations, TXT/Markdown for messages, or another format only when useful. Do not merely tell the human to design or copy these artifacts later.
3. Separate agent and human authority. The AI drafts; it does not send. An already authorized human may contact suppliers without another invented permission gate. Information gathering is not a purchase.
4. Give the full transition: open/use the supplied kit, send the prepared request by the authorized human, receive and record the response or explicit no-response state, then hand over to the named role. Preserve dependencies and the actual limits on decisions.
5. If a critical input is missing, say exactly what it is, its known source (or source unknown), and the dependent step it blocks. Prepare unaffected work but do not call the blocked part ready. Ask a question only if it prevents a useful bounded result.
6. Include only relevant clarification, escalation and disagreement paths. Do not add all four branches mechanically, hide refusal or turn silence into consent. Existing obligations still matter.
7. Check that the human can execute the known part without guessing a process. Verify that created files exist and are readable; return a short action order with links to those files. If file tools are unavailable or writing is unauthorized, give the complete usable content inline and disclose that limitation. Never claim an attachment exists unless it was actually created. Preserve internal handoff deadlines as internal conditions; do not turn them into unsupported supplier obligations or new approval gates.

## Readable result
A concise instruction saying what to open/use/do, where to send the result and when it is complete, followed by the actual prepared message/table/artifacts. State material blockers and decision limits visibly. No external action has been performed by the AI.

## Machine result (1.1)
Keep steps (id, actor, action, evidence_refs, output, depends_on), decision_owner, branches, message and do_not_decide. Add artifacts (name, content, evidence_refs) for actual inline prepared content, and blockers (missing, source, blocked_step). An artifact name is an inline label, not proof of a written or attached file. Dependencies and blocker step IDs must resolve. Include only applicable branches; schema 1.0 retains its historical four-branch requirement.

## Stop and failure conditions
Refuse fabricated consent, hidden refusal, unauthorized purchases or exploiting exhaustion. Clarify material authority contradictions. Separate incomplete inputs, unprepared artifacts, hidden work, unnecessary approvals and unclear handoffs in review: they are different utility defects.
